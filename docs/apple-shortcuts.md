# Apple 단축어 연동 가이드

iPhone·iPad·Mac의 **단축어(Shortcuts)** 앱에서 원탭으로 E-ink 화면을 바꾸는 방법입니다.
서버는 `https://` 로 공개되어 있고, 단축어는 **API 키**(`X-API-Key` 헤더)로 인증합니다.

## 왜 "마스터 단축어" 방식인가

과거에는 서버가 `.shortcut` 파일을 생성해 내려주는 방식을 시도했지만,
iOS 15+ / macOS Monterey+ 부터는 **서명되지 않은 단축어 파일 설치가 OS 레벨에서 차단**됩니다.

대신 아래처럼 동작하는 단축어를 **딱 하나만** 직접 만들어 두면 됩니다.

```
GET  /api/shortcuts/names      →  프리셋 이름 목록 (줄바꿈 구분 텍스트)
      ↓ 텍스트 분리 → 목록에서 선택
POST /api/shortcuts/activate   →  {"name": "<선택한 이름>"}
```

프리셋을 추가·삭제해도 단축어를 수정할 필요가 없습니다. 목록은 매번 서버에서 받아옵니다.
이름 목록을 JSON이 아닌 **일반 텍스트**로 받는 이유는, 단축어 앱의 JSON 파싱이 이모지가 섞인 문자열에서 불안정하기 때문입니다.

## 준비: 주소와 API 키

| 값 | 어디서 | 예 |
|----|--------|----|
| 서버 주소 | 공개 도메인 | `https://<도메인>.duckdns.org` |
| API 키 | 서버의 `server/.env` 에 있는 `API_KEY` | 무작위 32자 이상 |

서버에 SSH 로 접속해 키를 확인합니다.

```bash
grep '^API_KEY=' ~/eink-status-board/server/.env
```

`API_KEY=` 뒤의 값이 키입니다. 안전한 방법(AirDrop, 비밀번호 관리자 등)으로 iPhone 에 옮기세요.
Admin 페이지는 키를 보여주지 않습니다. 키는 `/api/shortcuts/names`, `/api/shortcuts/activate` 두 경로에서만 통합니다.
`.env` 에 `API_KEY` 가 비어 있으면 서버가 단축어 경로를 로그인 세션에만 열어 두므로 단축어가 `401` 을 받습니다.

## 만들기 (약 2분)

Admin 페이지 하단의 **서버 설정**에 외부 URL(`https://<도메인>.duckdns.org`)을 저장해 두면 (이 브라우저에만 저장됩니다),
같은 페이지의 가이드 카드에 아래 주소가 자동으로 채워집니다.
이 입력칸은 **`https://` 주소만 받습니다** (`http://` 는 `localhost`/`127.0.0.1` 만 예외). 단축어가 `X-API-Key` 를 실어 보내므로, 키가 평문으로 나가지 않게 하려는 제한입니다. 단축어 안의 URL 도 반드시 `https://` 로 적으세요.

| # | 동작 | 설정 |
|---|------|------|
| 1 | **URL** | `https://<도메인>.duckdns.org/api/shortcuts/names` |
| 2 | **URL의 콘텐츠 가져오기** | 방법: GET · 더 보기(화살표) → **헤더** → **새로운 헤더 추가** → 키 `X-API-Key`, 값 **API 키** |
| 3 | **텍스트 분리** | 분리 기준: **새로운 줄** |
| 4 | **목록에서 선택** | 입력: 3번 결과 |
| 5 | **URL** | `https://<도메인>.duckdns.org/api/shortcuts/activate` |
| 6 | **URL의 콘텐츠 가져오기** | 방법: **POST** · 헤더 `X-API-Key` = **같은 API 키** · 요청 본문: **JSON** · 필드 추가(텍스트) → 키 `name`, 값 **선택한 항목** |

**헤더는 2번과 6번, 두 "URL의 콘텐츠 가져오기" 동작 모두에 넣어야 합니다.** 하나만 빠져도 그 요청이 `401` 로 거부됩니다.

단축어 이름은 "E-ink 갱신"처럼 짓고, 제어 센터·위젯·메뉴 막대·Siri 어디에 붙여도 됩니다. 셀룰러 환경에서도 동작합니다 (서버가 80/443 을 전 세계에 열어 두고 키로 인증합니다).

### 옵션: 강제로 다시 그리기 (`force`)

6번의 요청 본문에 **불리언(Boolean)** 필드를 추가해 키 `force`, 값 켜짐(true)으로 두면 같은 화면이어도 패널을 다시 그립니다.
서버가 같은 이미지는 전송하지 않고, 펌웨어도 같은 프레임은 다시 그리지 않는 것이 기본 동작입니다. `force` 는 두 단계를 모두 건너뜁니다.

- 잔상이 남았을 때만 쓰세요. 전자잉크는 갱신 횟수가 수명이므로 매번 `force` 를 켜 두는 것은 권하지 않습니다. (`force` 여도 3초 이내 연타는 서버가 하나로 합칩니다)
- 잔상 제거만이 목적이면 Admin 의 **강제 새로고침**이 더 간단합니다.

## 특정 프리셋 전용 단축어

메뉴 선택 없이 바로 하나를 적용하려면 5·6번 동작만 넣고 `name`에 프리셋 이름을 고정합니다. (`X-API-Key` 헤더는 그대로 필요합니다)
"회의 중" 단축어를 캘린더 자동화(회의 시작 시 실행)에 연결하는 식으로 활용할 수 있습니다.

## 문제 해결

| 증상 | 원인 / 조치 |
|------|-------------|
| **`401` / 응답 `로그인이 필요합니다.`** | `X-API-Key` 헤더가 없거나 키가 틀림. 2번·6번 **두 동작 모두** 헤더 이름이 정확히 `X-API-Key` 인지, 값에 공백·줄바꿈이 섞이지 않았는지 확인. 서버 `.env` 의 `API_KEY` 가 비어 있거나 수정 후 재시작하지 않은 경우도 같은 증상 |
| 목록 선택 창에 `{"detail":"로그인이 필요합니다."}` 한 줄만 보임 | 2번 요청이 `401` 을 받은 것. 위 `401` 항목과 동일 |
| 목록이 비어 있음 | Admin 에서 프리셋이 하나도 없음. `curl` 로 `/api/shortcuts/names` 를 호출해 확인 (아래 예시). 브라우저에서 URL 을 직접 열면 Admin 에 로그인한 상태에서만 목록이 보입니다 (브라우저는 API 키가 아니라 세션 쿠키로 인증) |
| `404 프리셋을 찾을 수 없습니다` | 이름이 서버의 것과 다름. 앞뒤 공백은 서버가 무시하지만 이모지·띄어쓰기는 정확히 같아야 함. 이름을 바꿨다면 고정 이름 단축어를 고쳐야 함 |
| 응답에 `"skipped": true` / `이미 표시 중 (전송 생략)` | **오류가 아님.** 지금 패널에 있는 것과 똑같은 프레임이라 서버가 전송을 생략한 것. 그래도 다시 그리고 싶으면 `force` 옵션 또는 Admin 의 강제 새로고침 |
| 응답에 `"deferred": true` / `잠시 후 화면에 반영됩니다` | **오류가 아님.** 직전 전송 후 3초 이내에 또 눌러서 서버가 요청을 합친 것 (같은 화면을 연달아 눌러 첫 전송이 아직 대기 중일 때도 이렇게 응답). 간격이 지나면 **마지막으로 고른 화면**이 한 번 표시됨 (연타해도 패널은 3초에 한 번만 갱신) |
| `skipped`·`deferred` 가 모두 `false` 인데 `clients_notified` 가 `0` | 연결된 ESP32 가 없음. Admin 의 디바이스 목록에서 접속 중인지 확인 |
| 인증서·"안전하지 않은 연결" 경고 | URL 이 `http://` 이거나 도메인 철자가 다름. 항상 `https://<도메인>.duckdns.org` 를 쓰세요. 서버는 `http://` 를 HTTPS 로 리다이렉트하지만, 그 첫 요청에서 API 키가 평문으로 한 번 전송됩니다 |
| 갑자기 모든 단축어가 `401` | 서버의 `API_KEY` 가 바뀜 (키 교체). 아래 "키 교체"대로 단축어를 갱신 |

## 키 교체

키가 유출됐거나 단축어를 다른 사람과 공유했다면 교체하세요. 단축어를 공유(내보내기)하면 **헤더에 넣은 키도 함께 전달됩니다.** 키를 넣은 단축어는 공유하지 마세요.

1. 서버에서 새 키 생성: `python3 -c "import secrets; print(secrets.token_urlsafe(32))"`
2. `nano ~/eink-status-board/server/.env` 에서 `API_KEY=` 값을 교체
3. `sudo systemctl restart eink-status-board` — 이전 키는 즉시 무효가 됩니다
4. 모든 단축어의 `X-API-Key` 값을 새 키로 수정 (2번·6번 두 곳)

유출된 키로 할 수 있는 일은 프리셋 이름 조회와 프리셋 활성화뿐입니다. 전체 권한 표는 [보안 모델](deploy-gcp.md#15-보안-모델)을 보세요.

## curl로 같은 동작 재현

키를 셸 히스토리에 남기지 않으려면 먼저 변수로 읽어 둡니다.

```bash
read -rs API_KEY && export API_KEY        # 붙여넣고 Enter (화면에 표시되지 않음)

# 이름 목록
curl -H "X-API-Key: $API_KEY" https://<도메인>.duckdns.org/api/shortcuts/names

# 이름으로 활성화
curl -X POST https://<도메인>.duckdns.org/api/shortcuts/activate \
  -H "X-API-Key: $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name": "회의 중"}'

# 같은 화면이어도 강제로 다시 그리기
curl -X POST https://<도메인>.duckdns.org/api/shortcuts/activate \
  -H "X-API-Key: $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name": "회의 중", "force": true}'
```

응답 예: `{"success":true,"message":"'회의 중' 활성화 완료","clients_notified":1,"skipped":false,"deferred":false}`

`X-API-Key` 대신 `Authorization: Bearer <API_KEY>` 헤더도 받아들입니다. 키가 없거나 틀리면 `401` 입니다.
